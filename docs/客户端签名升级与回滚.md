# 客户端签名升级与回滚

服务器只保存 Ed25519 公钥，私钥保留在离线发布机。手机端只提示已签名版本，绝不会静默安装。

## 1. 生成签名清单

```bash
chmod +x deploy/sign-client-release.sh
./deploy/sign-client-release.sh 9.3.0 stable http://192.168.1.10/downloads/agent-v93.apk <APK_SHA256> 10 "首批10%设备"
```

首次运行会在 `release/keys` 生成密钥，并在 `release/manifests` 生成可直接提交接口的 JSON。必须单独备份私钥，不能上传 GitHub，也不能复制到服务器。把输出的 `CLOUD_UPDATE_PUBLIC_KEY` 写入服务器 `.env` 后重启服务。

## 2. 发布与启用

使用管理员 JWT 调用以下接口：

```bash
curl -X POST http://服务器IP/api/v1/client-updates -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" --data @release/manifests/client-release-9.3.0-stable.json
curl -X POST http://服务器IP/api/v1/client-updates/versions/9.3.0/activate -H "Authorization: Bearer $TOKEN"
```

`rollout_percent` 可设置为 1 到 100。同一设备会被稳定地分配到灰度批次，不会每次检查随机变化。

## 3. 回滚

```bash
curl -X POST http://服务器IP/api/v1/client-updates/channels/stable/rollback -H "Authorization: Bearer $TOKEN"
```

回滚会把上一份签名版本重新设为活动版本。手机仅保存待确认清单并提示管理员；实际 APK 安装仍需要人工确认。
