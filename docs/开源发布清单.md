# 全量源码公开发布清单

这份清单用于将当前工程发布为“全部自有源代码公开、禁止商业使用”的公开仓库。

核心原则：所有自有源代码都公开；只排除秘密、生产数据、构建缓存以及无权再分发的第三方文件。

## 1. 必须公开的内容

- `server/`：完整服务端源码、数据库迁移、测试和安全配置模板。
- `web/`：完整管理后台源码、依赖清单和构建配置。
- `client/`：完整手机端自有源码、连接层、任务层、配置界面和自有资源。
- `deploy/`：部署、健康检查、备份、升级和回滚脚本。
- `docs/`：架构、协议、稳定性、运维和部署文档。
- 根目录编排文件、示例环境变量文件和构建配置。
- `README.md`、`OPEN_SOURCE.md`、`LICENSE` 及必要的第三方声明。

不能因为模块涉及具体业务就删除自有源代码。公开说明可以只介绍通用技术能力，但仓库中的自有实现应完整保留。

## 2. 必须排除的内容

- `.env`、生产配置、密码、令牌、Webhook、私钥和证书口令。
- 数据库文件、备份、日志、截图、上传文件和真实设备信息。
- 内部域名、内网拓扑、个人信息和未脱敏测试数据。
- IDE 缓存、依赖缓存、临时目录和调试输出。
- 含生产信息或未完成审查的构建安装包。
- 没有再分发许可的第三方 SDK、二进制文件和素材。

如果第三方组件无法随仓库发布，应提供名称、版本、校验值、官方下载地址和放置路径，不应把第三方代码伪装成项目自有代码。

## 3. 非商业许可证检查

- 仓库根目录必须包含未经修改的 `LICENSE`。
- README 首屏应明确标注“源码公开、禁止商业使用”。
- 所有发布包应包含 `LICENSE`。
- 源码归档、容器镜像和手机安装包的下载页应显示许可证名称。
- 不应使用 MIT、Apache-2.0、BSD 或其他允许商业使用的项目徽章。
- 第三方依赖继续使用各自许可证；本项目许可证不能改变第三方授权范围。
- 接受外部贡献前，应确认贡献者同意其贡献按本项目许可证发布。

## 4. 敏感信息检查

发布前至少检查：

- 域名、IP 地址、邮箱、手机号和内部文件路径。
- `password`、`token`、`secret`、`private_key`、`webhook` 等字段。
- PEM 私钥、SSH 密钥、签名密钥和证书口令。
- 数据库连接串、对象存储凭据和第三方服务密钥。
- 日志、注释、截图和测试数据中的真实身份信息。
- Git 历史中已经删除但仍能恢复的敏感内容。

配置模板应只使用安全占位值：

```dotenv
SERVER_ADDRESS=192.168.1.10
ADMIN_PASSWORD=CHANGE_ME
DEVICE_TOKEN=
```

发现真实密钥时，不能只从最新文件中删除，还必须立即吊销或轮换该密钥，并清理 Git 历史。

## 5. 完整性检查

- 从一个空目录按照计划复制公开内容，确认所有自有源码均在其中。
- 检查手机端和服务端之间的协议字段是否同时公开。
- 检查构建脚本引用的本地文件是否已经提交，或者有合法获取说明。
- 检查文档没有依赖仅内部人员知道的部署步骤。
- 检查公开仓库不存在只有二进制文件、没有对应自有源码的模块。

## 6. 构建与质量验证

- 服务端执行格式检查、静态检查和完整测试。
- 管理后台安装锁定依赖并完成生产构建。
- 手机端在干净环境中完成构建或脚本加载验证。
- 使用全新数据库启动，确认迁移可以重复执行。
- 验证 MQTT、WebSocket、心跳、ACK、重连和离线补发。
- 验证即时任务、定时任务、超时、重试和错过执行策略。
- 验证备份、恢复、健康检查、磁盘保护、升级和回滚。
- 使用干净的 Ubuntu 24.04 或 26.04 环境跑通一键安装。

## 7. 正式发布验证

- 查看最终公开文件列表和完整 Git diff。
- 检查 Git 提交历史，确保历史版本也没有秘密或生产数据。
- 从公开仓库重新克隆，严格按公开文档完成构建和部署。
- 检查生成的每个发布包都包含许可证。
- 检查发布页面明确说明非商业限制和商业授权要求。

同时满足“全部自有源码可以取得”“干净环境能够构建”“没有秘密和生产数据”“许可证随所有副本分发”后，才算完成公开发布。
