# 生产级云控优化说明

稳定版仍保持现有业务协议和管理页面，主要改造连接层、投递层、数据库和运维层。

## 稳定性改造

- WS/MQTT 共用一套业务消息处理；同一设备只保留一个主通道。
- 心跳进入内存缓冲后批量写库，服务退出前强制刷盘。
- hub 注册、数据库、媒体任务均使用有界队列，避免无限堆积。
- 截图帧缓存限制为 128 MiB，并在过期或断线时回收。
- 告警使用固定并发 worker 和复用 HTTP Client；日志与截图分批清理。
- MySQL 连接池设有连接数、空闲数和生命周期上限。
- 命令通过持久化 outbox、ACK 和有限重试承受短时断线与服务重启。

## 性能与观测

- 为设备状态、任务状态和日志时间范围查询增加组合索引。
- `/metrics` 输出在线数、hub 队列深度、数据库连接状态及可靠投递状态。
- `/healthz` 只表示进程存活；`/readyz` 会实际检查数据库。
- MySQL sidecar 每 6 小时生成一致性压缩备份，默认保留 14 天。

## 扩展边界

单实例稳定版适合先完成可靠性灰度。需要 API 多副本时，在线状态、命令路由和调度器主节点选举仍需引入共享状态或消息总线；在完成这些工作前不要直接把 server 副本数调大，否则设备连接可能位于另一实例，且定时任务可能重复执行。

图片、APK 和大文件继续使用本地 Docker volume。跨主机部署前需迁移到对象存储；MySQL 备份也应复制到异机或对象存储，不能只保留在同一台宿主机。
